= 了解 Active IQ Unified Manager 如何使用作業物件進行非同步處理
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
Active IQ Unified Manager 提供 `jobs` API，用於擷取執行其他 API 時所執行之作業的相關資訊。您必須了解如何使用作業物件進行非同步處理。

某些 API 呼叫，特別是用於新增或修改資源的呼叫，可能需要比其他呼叫更長的時間才能完成。Unified Manager 會非同步處理這些長時間執行的要求。



[[asynchronous-requests-described-using-job-object]]
== 使用 Job 物件描述的非同步請求

在進行非同步執行的 API 呼叫後，HTTP 回應代碼 202 表示請求已成功驗證並被接受，但尚未完成。此請求會作為背景工作進行處理，在向用戶端發出初始 HTTP 回應後仍會繼續執行。回應中包含錨定該請求的 Job 物件，以及其唯一識別碼。



[[query-the-job-object-associated-with-an-api-request]]
== 查詢與 API 請求相關聯的 Job 物件

HTTP 回應中傳回的 Job 物件包含多個屬性。您可以查詢 state 屬性來決定請求是否成功完成。Job 物件可以處於以下狀態之一：

* `NORMAL`
* `WARNING`
* `PARTIAL_FAILURES`
* `ERROR`


在輪詢 Job 物件以偵測任務的終止狀態（成功或失敗）時，可以使用兩種技術：

* 標準輪詢要求：立即傳回目前的作業狀態。
* 長輪詢請求：當作業狀態變成 `NORMAL, ERROR,`或 `PARTIAL_FAILURES.`




[[steps-in-an-asynchronous-request]]
== 非同步請求中的步驟

您可以使用下列高階程序來完成非同步 API 呼叫：

. 發出非同步 API 呼叫。
. 收到 HTTP 回應 202，表示請求已成功接受。
. 從回應正文中提取 Job 物件的識別碼。
. 在迴圈中，等待 Job 物件達到終端狀態 `NORMAL, ERROR,`或 `PARTIAL_FAILURES.`
. 驗證作業的終止狀態並擷取作業結果。
