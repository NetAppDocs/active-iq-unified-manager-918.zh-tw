= 了解 Active IQ Unified Manager 中的工作負載分析器資料
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
工作負載分析器頁面顯示有關可能影響工作負載的任何當前事件的資訊、修復導致該事件的問題的建議，以及用於分析效能和容量歷史記錄的圖表。

在頁面頂部，您可以指定要分析的工作負載（Volume 或 LUN）的名稱，以及要檢視統計資料的時間範圍。如果您想檢視更短或更長的期間，可以隨時變更時間範圍。

頁面的其他區域顯示分析結果以及效能和容量圖表。

[NOTE]
====
LUN 的工作負載圖表未提供與 Volume 圖表相同層級的統計資料，因此在分析這兩種類型的工作負載時，您會注意到差異。

====
* *事件總結區*
+
顯示該時間段內發生的事件數量與類型的簡要總覽。當有來自不同影響領域（例如效能和容量）的事件時，會顯示此資訊，以便您選擇感興趣之事件類型的詳細資訊。按一下事件類型以檢視事件名稱清單。

+
如果在該時間範圍內只有一個事件，則會針對某些事件列出解決該問題的建議清單。

* *事件時間表*
+
顯示指定時間範圍內發生的所有事件。將游標懸停在每個事件上即可檢視事件名稱。

+
如果您是透過點擊事件詳細資料頁面中的 *Analyze Workload* 按鈕進入此頁面，則所選事件的圖示會放大，以便您識別該事件。

* *效能圖表區域*
+
根據您選取的時間範圍，顯示延遲、處理量（IOPS 和 MB/s）以及使用率（節點和彙總）的圖表。您可以按一下「檢視效能詳細資料」連結來顯示工作負載的 Performance Explorer 頁面，以便執行進一步的分析。

+
** *延遲* 顯示所選時間範圍內工作負載的延遲。此圖表包含三種檢視，可讓您查看：
+
*** *總*延遲
*** *細分*延遲（依讀取、寫入及其他程序細分）
*** *叢集元件*延遲（按叢集元件細分）






請參閱 link:concept_cluster_components_and_why_they_can_be_in_contention.html["叢集元件及其可能發生爭用的原因"] 以取得此處顯示之叢集元件的執行摘要。** *處理量* 顯示所選時間範圍內工作負載的 IOPS 和 MB/s 處理量。此圖表有四個檢視，可讓您查看：*** *總* 處理量 *** *細目* 處理量（依讀取、寫入及其他程序細分）*** *雲端處理量*（用於將資料寫入雲端及從雲端讀取資料的 MB/s；適用於將容量分層至雲端的工作負載）*** *含預測的 IOPS*（預測在該時間範圍內預期的 IOPS 處理量上限與下限值）如果已設定，此圖表也會顯示服務品質（QoS）最大與最小處理量臨界值設定，以便您查看系統可能透過 QoS 原則刻意限制處理量的位置。** *使用率* 顯示所選時間範圍內執行工作負載之彙總與節點的使用率。從這裡您可以查看彙總或節點是否過度使用，這可能會導致高延遲。在分析 FlexGroup Volume 時，使用率圖表上會列出多個節點與多個彙總。

* *容量圖區*
+
顯示過去一個月工作負載的資料容量和 Snapshot 快照技術容量圖表。

+
對於 Volume，您可以按一下「檢視容量詳細資料」連結，以顯示工作負載的「健全狀況詳細資料」頁面，以便進行進一步的分析。LUN 不提供此連結，因為 LUN 沒有「健全狀況詳細資料」頁面。

+
** *容量檢視* 顯示指派給工作負載的總可用空間和邏輯已使用空間（經過所有 NetApp 最佳化後）。
** *Snapshot 快照技術檢視* 顯示為 Snapshot 快照技術副本預留的總空間，以及目前正在使用的空間量。請注意，LUN 不提供 Snapshot 快照技術檢視。
** *Cloud Tier 檢視*顯示本機效能分層中已使用的容量，以及雲端分層中已使用的容量。這些圖表包含此工作負載容量滿載前剩餘時間的估計值。此資訊是根據歷史使用量而定，至少需要 10 天的資料。當剩餘容量不到 30 天時， Unified Manager 會將儲存設備識別為 "`almost full`"。
