= 在 Active IQ Unified Manager 中識別效能事件中的工作負載角色
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
Unified Manager 使用角色來識別工作負載在效能事件中的參與程度。這些角色包括受害者、霸凌者和鯊魚。使用者定義的工作負載可以同時扮演受害者、霸凌者和鯊魚的角色。

|===
| 角色 | 說明 


 a| 
受害者
 a| 
使用者自訂工作負載因其他工作負載（稱為「霸凌者」）過度使用叢集元件而導致效能下降。只有使用者自訂工作負載才會被識別為受害者。Unified Manager 根據延遲偏差來識別受害者工作負載，即在事件發生期間，實際延遲與其延遲預測值（預期範圍）相比顯著增加。



 a| 
霸凌
 a| 
使用者定義或系統定義的工作負載，其過度使用叢集元件，導致其他工作負載（稱為受害者）的效能下降。Unified Manager 會根據叢集元件使用量的偏差來識別霸凌型工作負載，其中在事件期間的實際使用量已大幅超出其預期的使用範圍。



 a| 
鯊魚
 a| 
與事件中涉及的所有工作負載相比，對叢集元件使用率最高的使用者定義工作負載。Unified Manager 會根據工作負載在事件期間對叢集元件的使用情況來識別鯊魚工作負載。

|===
叢集上的工作負載可以共享許多叢集元件，例如彙總以及用於網路和資料處理的 CPU。當某個工作負載（例如 Volume）對叢集元件的使用量增加到該元件無法有效滿足工作負載需求的程度時，該元件就會處於爭用狀態。過度使用叢集元件的工作負載被稱為「霸凌者」。其他共享這些元件且效能受到「霸凌者」影響的工作負載則稱為「受害者」。系統定義的工作負載（例如重複資料刪除或 Snapshot 快照技術複本）的活動也可能提報為「\`bullying\`」。

當 Unified Manager 偵測到事件時，它會識別所有涉及的工作負載和叢集元件，包括導致事件的霸凌工作負載、發生爭用的叢集元件以及由於霸凌工作負載活動增加而導致效能下降的受害工作負載。

[NOTE]
====
如果 Unified Manager 無法辨識霸凌工作負載，則只會對受害工作負載和涉及的叢集元件發出警報。

====
Unified Manager 可以識別身為惡霸工作負載受害者的工作負載，也能識別這些相同的工作負載何時成為惡霸工作負載。工作負載本身也可能成為惡霸。例如，受到原則群組限制而受到節流的高效能工作負載，會導致原則群組中的所有工作負載（包括其本身）都受到節流。在後續的效能事件中，身為惡霸或受害者的工作負載可能會改變其角色，或不再參與該事件。
