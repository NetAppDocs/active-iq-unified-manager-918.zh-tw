= 了解 Active IQ Unified Manager 中系統定義的效能臨界值原則
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
Unified Manager 提供一些標準臨界值原則，用於監控叢集效能並自動產生事件。這些原則預設為啟用，當超過監控的效能臨界值時，它們會產生警告或資訊事件。

[NOTE]
====
Cloud Volumes ONTAP、ONTAP Edge 或 ONTAP Select 系統未啟用系統定義的效能臨界值原則。

====
如果您收到來自任何系統定義的效能臨界值原則的不必要事件，您可以從「事件設定」頁面停用個別原則的事件。



[[cluster-threshold-policies]]
== 叢集臨界值原則

預設情況下，系統定義的叢集效能臨界值原則會指派給 Unified Manager 監控的每個叢集：

* *叢集負載不平衡*
+
識別叢集中一個節點的負載遠高於其他節點的情況，這可能會影響工作負載延遲。

+
它透過比較叢集中所有節點的已使用效能容量值，來判斷是否有任何節點超過 30% 的臨界值超過 24 小時。這是一個警告事件。

* *叢集容量不平衡*
+
識別出叢集中某個彙總的已使用容量遠高於其他彙總的情況，因此可能會影響作業所需的空間。

+
它會比較叢集中所有彙總的已使用容量值，以查看任何彙總之間是否有 70% 的差異。這是一個警告事件。





[[node-threshold-policies]]
== 節點臨界值原則

預設情況下，系統定義的節點效能臨界值原則會指派給 Unified Manager 監控的叢集中的每個節點：

* *效能容量使用率已超過臨界值*
+
識別單一節點運作超出其作業效率範圍的情況，進而可能影響工作負載延遲。

+
它會尋找使用超過 100% 效能容量且持續超過 12 小時的節點。這是一個警告事件。

* *節點 HA 配對過度利用*
+
識別 HA 配對的節點運作超出 HA 配對作業效率範圍的情況。

+
它透過查看 HA 配對中兩個節點的已使用效能容量值來達成此目的。如果兩個節點的已使用效能容量總和超過 200% 且持續超過 12 小時，則控制器容錯移轉將會影響工作負載延遲。這是一個資訊事件。

* *節點磁碟碎片化*
+
識別彙總中一或多個磁碟碎片化的情況，這會減緩關鍵系統服務的速度，並可能影響節點上的工作負載延遲。

+
它透過檢查節點上所有彙總的特定讀取與寫入作業比率來實現這一點。此原則也可能在 SyncMirror 重新同步期間，或在磁碟清理作業期間發現錯誤時觸發。這是一個警告事件。

+
[NOTE]
====
"`Node disk fragmentation`" 原則會分析純 HDD 彙總；Flash Pool、SSD 和 FabricPool 彙總則不予分析。

====




[[aggregate-threshold-policies]]
== 彙總臨界值原則

系統定義的彙總效能臨界值原則預設指派給 Unified Manager 監控的叢集中的每個彙總：

* *彙總磁碟過度利用*
+
識別彙總超出其作業效率極限的情況，從而可能影響工作負載延遲。它透過尋找其中磁碟使用率超過 95% 且持續時間超過 30 分鐘的彙總來識別這些情況。然後，此多條件原則執行以下分析，以幫助確定問題的原因：

+
** 彙總中的磁碟目前是否正在進行背景維護活動？
+
磁碟可能進行的一些背景維護活動包括磁碟重建、磁碟清理、SyncMirror 重新同步和重新計算同位元。

** 磁碟櫃 Fibre Channel 互連是否存在通訊瓶頸？
** 彙總中的可用空間是否過少？只有當三個子原則中的一個（或多個）也被判定為違反時，才會針對此原則發出警告事件。如果僅彙總中的磁碟使用率超過 95%，則不會觸發效能事件。




[NOTE]
====
"\`Aggregate disks over-utilized\`" 原則分析僅包含 HDD 的彙總和 Flash Pool （混合）彙總；不分析 SSD 和 FabricPool 彙總。

====


[[workload-latency-threshold-policies]]
== 工作負載延遲臨界值原則

系統定義的工作負載延遲臨界值原則會指派給任何已設定效能服務層級原則，且具有已定義 "`expected latency`" 值的工作負載：

* *工作負載 Volume/LUN 延遲臨界值已超出效能服務層級定義的範圍*
+
識別已超出 "`預期延遲`" 限制且影響工作負載效能的 Volumes（檔案共享）和 LUN。這是一個警告事件。

+
它的作法是尋找在過去一小時內，有 30% 的時間超過預期延遲值的工作負載。





[[qos-threshold-policies]]
== QoS 臨界值原則

系統定義的 QoS 效能臨界值原則會指派給任何已設定 ONTAP QoS 最大處理量原則（IOPS、IOPS/TB 或 MB/s）的工作負載。當工作負載處理量值比設定的 QoS 值低 15% 時，Unified Manager 會觸發事件：

* *QoS 最大 IOPS 或 MB/s 臨界值*
+
識別已超出其 QoS 最大 IOPS 或 MB/s 處理量限制，並影響工作負載延遲的 Volume 和 LUN。這是一個警告事件。

+
當將單一工作負載指派給原則群組時，它會尋找在前一個小時的每個收集週期內超過已指派 QoS 原則群組中定義的最大處理量臨界值的工作負載。

+
當多個工作負載共享單一 QoS 原則時，它會將原則中所有工作負載的 IOPS 或 MB/s 相加，並將總和與臨界值進行比較。

* *QoS 峰值 IOPS/TB 或具有區塊大小臨界值的 IOPS/TB*
+
識別已超過其具調適能力的 QoS 峰值 IOPS/TB 處理量限制（或帶區塊大小限制的 IOPS/TB）且影響工作負載延遲的 Volume。這是一個警告事件。

+
它透過將具調適能力的 QoS 原則中定義的峰值 IOPS/TB 臨界值轉換為基於每個 Volume 大小的 QoS 最大 IOPS 值來實現這一點，然後尋找在前一小時的每個效能收集週期內超過 QoS 最大 IOPS 的 Volume。

+
[NOTE]
====
只有當叢集安裝 ONTAP 9.3 及更新版本軟體時，此原則才會套用至 Volume。

====
+
當具調適能力的 QoS 原則中定義了「`區塊大小`」元素後，臨界值會根據每個 Volume 的大小轉換為 QoS 最大 MB/s 值。然後，它會尋找在前一小時的每個效能收集週期內超過 QoS 最大 MB/s 值的 Volume。

+
[NOTE]
====
只有當叢集安裝 ONTAP 9.5 及更新版本軟體時，此原則才會套用至 Volume。

====
