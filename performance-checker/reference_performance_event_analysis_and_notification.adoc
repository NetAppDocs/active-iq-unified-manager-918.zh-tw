= 在 Active IQ Unified Manager 中分析效能事件和通知
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
效能事件會通知您工作負載上的 I/O 效能問題，該問題是由叢集元件上的爭用引起的。Unified Manager 會分析該事件，以識別所有涉及的工作負載、發生爭用的元件，以及該事件是否仍是您可能需要解決的問題。

Unified Manager 會監控叢集中 Volume 的 I/O 延遲（回應時間）和 IOPS （作業）。例如，當其他工作負載過度使用叢集元件時，該元件就會出現資源爭用，無法以最佳層級滿足工作負載需求。使用相同元件的其他工作負載的效能可能會受到影響，導致其延遲增加。如果延遲超過動態效能臨界值， Unified Manager 將觸發效能事件通知您。



[[event-analysis]]
== 事件分析

Unified Manager 使用前 15 天的效能統計資料執行下列分析，以識別事件中涉及的受害工作負載、霸凌工作負載和叢集元件：

* 識別延遲已超過動態效能臨界值（即延遲預測的上限）的受害工作負載：
+
** 對於 HDD 或 Flash Pool 混合彙總（本機分層）上的 Volume，僅當延遲大於 5 毫秒（ms）且 IOPS 大於每秒 10 次作業（ops/sec）時，才會觸發事件。
** 對於全 SSD 彙總或 FabricPool 彙總（雲端分層）上的 Volume ，只有當延遲大於 1 ms 且 IOPS 大於 100 ops/sec 時，才會觸發事件。


* 識別發生爭用的叢集元件。
+
[NOTE]
====
如果叢集互連處受害工作負載的延遲大於 1 毫秒，Unified Manager 會將此視為重大問題，並觸發叢集互連事件。

====
* 識別過度使用叢集元件並導致其處於爭用狀態的惡霸工作負載。
* 根據叢集元件的使用率或活動偏差，對所涉及的工作負載進行排名，以確定哪些惡霸對叢集元件的使用量變化最大，以及哪些受害者受到的影響最大。


事件可能僅持續片刻，並在其使用的元件不再處於爭用狀態後自行修正。持續事件是指在五分鐘間隔內針對同一叢集元件重複發生並保持作用中狀態的事件。對於持續事件， Unified Manager 在連續兩個分析間隔內偵測到相同事件後會觸發警報。

事件解決後，它會作為 Volume 過去效能問題記錄的一部分保留在 Unified Manager 中。每個事件都有一個唯一的 ID，用於識別事件類型以及涉及的 Volume、叢集和叢集元件。

[NOTE]
====
單一 Volume 可以同時參與多個事件。

====


[[event-state]]
== 事件狀態

事件可以處於以下幾種狀態之一：

* *作用中*
+
表示效能事件目前處於作用中（新建或已確認）。導致該事件的問題尚未自行修正或解決。儲存設備物件的效能計數器仍高於效能臨界值。

* *已過時*
+
表示該事件已不再作用中。導致該事件的問題已自行修正或已解決。儲存設備物件的效能計數器已不再高於效能臨界值。





[[event-notification]]
== 事件通知

事件會顯示在儀表板頁面和使用者介面中的許多其他頁面上，並且這些事件的警報會傳送到指定的電子郵件地址。您可以在事件詳細資料頁面和工作負載分析頁面上檢視有關事件的詳細分析資訊，並取得解決該事件的建議。



[[event-interaction]]
== 事件互動

在「事件詳情」頁面和「工作負載分析」頁面上，您可以透過以下方式與事件互動：

* 將滑鼠移至事件上方會顯示一則訊息，顯示偵測到該事件的日期和時間。
+
如果在同一時間段內發生多個事件，則訊息會顯示事件數量。

* 按一下單一事件會顯示一個對話方塊，其中顯示有關該事件的更詳細資訊，包括所涉及的叢集元件。
+
發生爭用的元件會以紅圈標示並以紅色醒目提示。您可以按一下 *檢視完整分析* ，在「事件詳細資料」頁面上檢視完整分析。如果同一時段內有多個事件，對話方塊會顯示最近三個事件的詳細資訊。您可以按一下某個事件，在「事件詳細資料」頁面上檢視事件分析。
