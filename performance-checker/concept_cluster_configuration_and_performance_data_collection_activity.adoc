= 在 Active IQ Unified Manager 中檢視叢集組態和效能資料
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
_叢集組態資料_的收集間隔為 15 分鐘。例如，新增叢集後，需要 15 分鐘才能在 Unified Manager UI 中顯示叢集詳細資料。對叢集進行變更時，也適用此間隔。

例如，如果您在叢集中的 SVM 中新增兩個新 Volume，則會在下一個輪詢間隔（最長可達 15 分鐘）後在 UI 中看到這些新物件。

Unified Manager 每五分鐘從所有受監控的叢集收集目前的 _效能統計資料_。它會分析這些資料，以識別效能事件和潛力問題。它保留 30 天的五分鐘歷史效能資料和 180 天的一小時歷史效能資料。這可讓您檢視當月非常精細的效能詳細資料，以及長達一年的整體效能趨勢。

收集輪詢會錯開幾分鐘，以免同時傳送來自每個叢集的資料，進而影響效能。

下表描述 Unified Manager 執行的收集活動：

|===
| 活動 | 時間間隔 | 說明 


 a| 
效能統計資料輪詢
 a| 
每隔 5 分鐘
 a| 
從每個叢集收集即時效能資料。



 a| 
統計分析
 a| 
每隔 5 分鐘
 a| 
每次統計資料輪詢後，Unified Manager 將收集到的資料與使用者定義、系統定義和動態臨界值進行比較。

如果違反任何效能臨界值，Unified Manager 將產生事件並傳送電子郵件給指定的使用者（如果已設定這麼做）。



 a| 
組態輪詢
 a| 
每隔 15 分鐘
 a| 
從每個叢集收集詳細的庫存資訊，以識別所有儲存設備物件（節點、SVM、Volume 等）。



 a| 
總結
 a| 
每小時
 a| 
將最近 12 次五分鐘效能資料收集結果匯總為每小時平均值。

某些使用者介面頁面會使用每小時平均值，這些平均值會保留 180 天。



 a| 
預測分析和資料修剪
 a| 
每天午夜之後
 a| 
分析叢集資料，為接下來的 24 小時建立 Volume 延遲和 IOPS 的動態臨界值。

從資料庫中刪除超過 30 天的五分鐘效能資料。



 a| 
資料修剪
 a| 
每天凌晨 2 點以後
 a| 
從資料庫中刪除超過 180 天的事件和超過 180 天的動態臨界值。



 a| 
資料修剪
 a| 
每天凌晨 3:30 之後
 a| 
從資料庫中刪除超過 180 天的任何一小時效能資料。

|===
