= 回應 Active IQ Unified Manager 中的節點資源過度利用事件
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
當單一節點的運作超出其作業效率的範圍，從而可能影響工作負載延遲時，Unified Manager 會產生節點資源過度利用警告事件。這些系統定義的事件提供了糾正潛力效能問題的商機，避免許多工作負載受到延遲的影響。

.開始之前
* 您必須擁有操作員、應用程式管理員或儲存管理員角色。
* 必須存在新的或已過時的效能事件。


Unified Manager 會針對節點資源過度利用原則違規行為產生警告事件，方法是尋找效能容量使用率超過 100% 且持續時間超過 30 分鐘的節點。

您可以使用 System Manager 或 ONTAP 命令來修正此類效能問題，包括下列工作：

* 為任何過度使用系統資源的 Volume 或 LUN 建立並套用 QoS 原則
* 降低已套用工作負載的原則群組的 QoS 最大處理量限制
* 將工作負載移至不同的彙總或節點
* 透過將磁碟新增至節點，或升級至具有更快 CPU 和更多 RAM 的節點來增加容量


.步驟
. 顯示 *事件詳細資料* 頁面以檢視事件的資訊。
. 請檢閱 *描述* ，其中說明導致事件的臨界值違規。
+
例如，訊息「`Perf.Capacity Used 值為 139%（在 simplicity-02 上）已觸發警告事件，以識別資料處理單元中的潛力效能問題。`」表示節點 simplicity-02 上的效能容量過度使用，影響了節點效能。

. 在 *System Diagnosis* 區段下，審查三個圖表：一個用於節點上已使用的效能容量，一個用於頂端工作負載所使用的平均儲存設備 IOPS，以及一個用於頂端工作負載的延遲。以此方式排列，您可以查看哪些工作負載是造成節點延遲的原因。
+
您可以透過將游標停留在 IOPS 圖表上來檢視哪些工作負載套用了 QoS 原則，哪些工作負載沒有套用。

. 在 *建議操作* 部分，審查建議並確定應執行哪些操作以避免工作負載延遲增加。
+
如果需要，請按一下 *說明* 按鈕來檢視更多詳細資訊，以了解您可以執行哪些建議動作來嘗試解決效能事件。
