= 在 Active IQ Unified Manager 中使用儲存設備 QoS 控制工作負載處理量
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
您可以建立服務品質（QoS）原則群組，以控制其包含的工作負載的每秒 I/O 操作數（IOPS）或處理量（MB/s）限制。如果工作負載位於未設定限制的原則群組（例如預設原則群組）中，或已設定的限制無法滿足您的需求，您可以提高限制，或將工作負載移至具有所需限制的新原則群組或現有原則群組。

"`傳統`" QoS 原則群組可以指派給個別工作負載；例如，單一 Volume 或 LUN。在這種情況下，工作負載可以使用完整的處理量限制。QoS 原則群組也可以指派給多個工作負載；在這種情況下，處理量限制在這些工作負載之間是 "`共享的`"。例如，指派給三個工作負載的 9,000 IOPS QoS 限制，將限制總 IOPS 不超過 9,000 IOPS。

「具調適能力的」 QoS 原則群組也可以指派給個別工作負載或多個工作負載。但是，即使指派給多個工作負載，每個工作負載也會獲得完整的處理量限制，而不是與其他工作負載共享處理量值。此外，具調適能力的 QoS 原則會根據每個工作負載的 Volume 大小自動調整處理量設定，從而在 Volume 大小變化時保持 IOPS 與 TB 的比率。例如，如果具調適能力的 QoS 原則中的峰值設定為 5,000 IOPS/TB，則 10 TB 的 Volume 的最大處理量為 50,000 IOPS。如果 Volume 稍後調整大小為 20 TB，具調適能力的 QoS 會將最大值調整為 100,000 IOPS。

從 ONTAP 9.5 開始，您可以在定義具調適能力的 QoS 原則時包含區塊大小。這樣，當工作負載使用非常大的區塊大小並最終佔用大量處理量時，原則會從 IOPS/TB 臨界值有效地轉換為 MB/s 臨界值。

對於共享的群組 QoS 原則，當原則群組中所有工作負載的 IOPS 或 MB/s 超過設定的限制時，原則群組會調節工作負載以限制其活動，這可能會降低原則群組中所有工作負載的效能。如果原則群組調節產生了動態效能事件，則事件執行摘要會顯示相關原則群組的名稱。

在「效能：所有 Volume」檢視中，您可以按 IOPS 和 MB/s 對受影響的 Volume 進行排序，以查看哪些工作負載的使用率最高，可能導致了該事件。在「效能 / Volume 資源管理器」頁面中，您可以選擇其他 Volume 或 Volume 上的 LUN，以與受影響工作負載的 IOPS 或 MBps 處理量使用情況進行比較。

透過將過度佔用節點資源的工作負載分配到更嚴格的原則群組設定中，原則群組可以限制這些工作負載的活動，從而降低該節點上的資源使用率。但是，如果您希望工作負載能夠使用更多的節點資源，則可以增加原則群組的值。

您可以使用 System Manager、ONTAP 命令或 Unified Manager 效能服務等級來管理原則群組，包括下列任務：

* 建立原則群組
* 在原則群組中新增或移除工作負載
* 在原則群組之間移動工作負載
* 更改原則群組的處理量限制
* 將工作負載移至不同的彙總和/或節點
