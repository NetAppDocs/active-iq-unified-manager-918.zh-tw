= 了解 Active IQ Unified Manager 如何計算預期效能範圍
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
延遲預測是預測在特定時間點的預期效能上限與下限值。對於工作負載延遲，上限值構成效能臨界值。當實際值超過效能臨界值時，Unified Manager 會觸發動態效能事件。

例如，在正常營業時間（上午 9:00 至下午 5:00），大多數員工可能會在上午 9:00 至 10:30 之間查看電子郵件。此時，郵件伺服器的需求增加，意味著後端儲存設備的工作負載活動也會增加。員工可能會注意到電子郵件用戶端的回應時間變慢。

在中午 12:00 到下午 1:00 的午餐時間，以及下午 5:00 之後的下班時間，大多數員工可能都不在電腦前。電子郵件伺服器的需求通常會下降，後端儲存設備的需求也會隨之降低。另一方面，下午 5:00 之後可能會有一些排定的工作負載作業，例如儲存設備備份或掃毒，這些作業會增加後端儲存設備的活動。

在數天的時間裡，工作負載活動的增減決定了活動的預期範圍（延遲預測），並設定了工作負載的上限和下限。當某個物件的實際工作負載活動超出上限或下限，並且持續一段時間超出範圍時，這可能表示該物件有過度使用或使用不足的情況。



[[how-the-latency-forecast-is-formed]]
== 延遲預測的形成方式

Unified Manager 必須至少收集 3 天的工作負載活動才能開始分析，並在 GUI 中顯示 I/O 回應時間的延遲預測。所需的最低資料收集無法將工作負載活動所發生的所有變更納入考量。在收集前 3 天的活動資料後，Unified Manager 會每隔 24 小時（凌晨 12:00）調整延遲預測，以反映工作負載活動的變化並建立更準確的動態效能臨界值。

[NOTE]
====
日光節約時間（DST）會改變系統時間，這會改變受監控工作負載之效能統計資料的延遲預測。Unified Manager 會立即開始修正延遲預測，這大約需要 15 天才能完成。在此期間，您可以繼續使用 Unified Manager，但由於 Unified Manager 使用延遲預測來偵測動態事件，因此某些事件可能不準確。在時間變更之前偵測到的事件不受影響。
