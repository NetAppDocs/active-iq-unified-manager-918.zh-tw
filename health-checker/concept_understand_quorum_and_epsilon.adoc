= 了解 Active IQ Unified Manager 中 ONTAP 叢集的法定人數與 Epsilon
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
法定人數與 epsilon 是衡量叢集健全狀況與功能的重要指標，兩者共同指出叢集如何應對潛力的通訊與連線挑戰。

_仲裁_是叢集正常運作的前提條件。當叢集處於仲裁狀態時，大多數節點都處於健全狀態，並且可以相互通訊。當失去仲裁時，叢集將失去執行正常叢集作業的能力。任何時候都只能有一組節點處於仲裁狀態，因為所有節點共同共享單一資料檢視。因此，如果允許兩個互不通訊的節點以不同的方式修改資料，則無法再將資料協調成單一資料檢視。

叢集中的每個節點都參與投票協議，該協議選舉一個節點作為主節點；其餘節點均為從節點。主節點負責同步叢集內的資訊。當叢集達到法定人數時，透過持續投票來維持法定人數。如果主節點離線且叢集仍處於法定人數狀態，則由保持線上的節點選出一個新的主節點。

由於在節點數為偶數的叢集中可能會出現平手的情況，因此其中一個節點會擁有額外的分數投票權重，稱為 epsilon。如果大型叢集中兩個相等部分之間的連線中斷，假設所有節點都處於健全狀態，則包含 epsilon 的節點群組將維持法定人數。例如，下圖顯示一個四節點叢集，其中兩個節點發生故障。然而，由於其中一個存活的節點擁有 epsilon，即使健全節點未達簡單多數，叢集仍會維持法定人數。

image::../media/epsilon_preserving_quorum.gif[這張映像由周圍的文字進行解釋。]

建立叢集時，Epsilon 會自動指派給第一個節點。如果持有 epsilon 的節點變得不健全、接管其高可用度合作夥伴，或被其高可用度合作夥伴接管，則 epsilon 會自動重新指派給不同 HA 配對中健全的節點。

將節點離線可能會影響叢集保持仲裁的能力。因此，如果您嘗試執行會導致叢集退出仲裁，或使其距離遺失仲裁僅差一次停電的操作，ONTAP 會發出警告訊息。您可以使用進階權限層級的 cluster quorum-service options modify 命令來停用仲裁警告訊息。

一般來說，假設叢集節點間連線可靠，較大的叢集比較小的叢集更穩定。在由 24 個節點組成的叢集中，維持半數節點加 epsilon 的簡單多數所需的法定人數要求，比在由 2 個節點組成的叢集中更容易。

雙節點叢集在維持法定人數方面面臨一些獨特的挑戰。雙節點叢集使用叢集 HA，其中兩個節點都不持有 epsilon；相反地，兩個節點都會被持續輪詢，以確保在一個節點發生故障時，另一個節點對資料具有完整的讀寫存取，以及對邏輯介面和管理功能的存取。
