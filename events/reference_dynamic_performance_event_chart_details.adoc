= 了解 Active IQ Unified Manager 中的動態效能事件
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
對於動態效能事件，「事件詳細資料」頁面的「系統診斷」區段會列出延遲最高，或對發生爭用之叢集元件使用率最高的前幾大工作負載。

效能統計資料是根據從偵測到效能事件到最後一次分析該事件的時間。圖表也會顯示發生爭用之叢集元件的歷史效能統計資料。

例如，您可以識別元件使用率高的工作負載，從而確定將哪些工作負載遷移到使用率較低的元件。遷移工作負載會減少目前元件的工作量，並可能使該元件脫離爭用狀態。本節頂部顯示的是偵測到事件及上次分析的時間和日期範圍。對於作用中事件（新事件或已確認事件），上次分析時間會更新。

將游標停留在延遲和活動圖表上時，圖表會顯示排名最高的工作負載名稱。按一下圖表右側的「工作負載類型」選單，您可以根據工作負載在事件中的角色對其進行排序（包括 _sharks_、_bullies_ 或 _victims_），並顯示有關其延遲及其在競爭叢集元件上使用情況的詳細資訊。您可以將實際值與預期值進行比較，以查看工作負載何時超出其預期的延遲或使用範圍。如需詳細資訊，請參閱 link:..//performance-checker/concept_types_of_workloads_monitored_by_unified_manager.html["Unified Manager 監控的工作負載類型"]。

[NOTE]
====
當您依延遲的峰值偏差進行排序時，系統定義的工作負載不會顯示在表格中，因為延遲僅適用於使用者定義的工作負載。延遲值極低的工作負載不會顯示在表格中。

====
如需有關動態效能臨界值的詳細資訊，請參閱link:../performance-checker/concept_analyze_events_from_dynamic_performance_thresholds.html["分析動態效能閾值事件"]。

如需有關 Unified Manager 如何對工作負載進行排名並決定排序順序的資訊，請參閱 link:../performance-checker/concept_how_um_determines_performance_impact_for_incident.html["Unified Manager 如何決定事件的效能影響"]。

圖表中的資料顯示上次分析事件前 24 小時的效能統計資料。每個工作負載的實際值和預期值是根據工作負載參與事件的時間而定。例如，工作負載可能在偵測到事件之後才參與事件，因此其效能統計資料可能與偵測到事件時的值不符。依預設，工作負載會依延遲的峰值（最高）偏差排序。

[NOTE]
====
由於 Unified Manager 最多保留 30 天的 5 分鐘歷史效能和事件資料，如果事件超過 30 天，則不會顯示任何效能資料。

====
* *工作負載排序欄*
+
** *延遲圖表*
+
顯示該事件對上次分析期間工作負載延遲的影響。

** *元件使用狀況欄*
+
顯示有關爭用叢集元件的工作負載使用情況詳細資訊。在圖表中，實際使用情況以藍線表示。紅色長條會突顯事件持續時間，從偵測時間到上次分析時間。如需詳細資訊，請參閱 link:../performance-checker/reference_workload_performance_measurement_values.html["工作負載效能測量值"]。

+
[NOTE]
====
對於網路元件，由於網路效能統計資料來自叢集外的活動，因此不顯示此欄。

====
** *組件使用情況*
+
顯示網路處理、資料處理和彙總元件的使用率歷史記錄（以百分比表示），或顯示 QoS 原則群組元件的活動歷史記錄（以百分比表示）。網路或互連元件不會顯示圖表。您可以指向統計資料，以檢視特定時間點的使用情況統計資料。

** *總寫入 MB/s 歷史記錄*
+
僅針對 MetroCluster 資源元件，顯示在 MetroCluster 組態中鏡射至合作夥伴叢集的所有 Volume 工作負載的總寫入處理量，單位為每秒百萬位元組 (MBps)。

** *事件歷程*
+
顯示紅色陰影線條，指示衝突元件的歷史事件。對於已過時的事件，圖表會顯示在偵測到所選事件之前和解決之後發生的事件。
