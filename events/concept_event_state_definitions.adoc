= Active IQ Unified Manager 中的事件狀態
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
事件狀態有助於您確定是否需要採取適當的修正行動。事件狀態可以是「新建」、「已確認」、「已解決」或「已過時」。請注意，「新建」和「已確認」事件均被視為作用中事件。

事件狀態如下：

* *新增*
+
新事件的狀態。

* *已確認*
+
當您確認事件時的事件狀態。

* *已解決*
+
事件被標記為已解決時的狀態。

* *已過時*
+
事件自動修正或事件原因不再有效時的狀態。

+
[NOTE]
====
您無法確認或解決已過時的事件。

====




[[example-of-different-states-of-an-event]]
== 事件的不同狀態範例

以下範例說明手冊和自動事件狀態變更。

當「叢集無法連線」事件觸發時，事件狀態為「新增」。確認事件後，事件狀態會變更為「已確認」。採取適當的修正行動後，您必須將事件標記為已解決。然後事件狀態會變更為「已解決」。

如果 Cluster Not Reachable 事件是由於停電所產生，則在恢復供電後，叢集無需任何系統管理員介入即可開始運作。因此，Cluster Not Reachable 事件不再有效，且事件狀態會在下一個監控週期中變更為過時。

當事件處於「已過時」或「已解決」狀態時，Unified Manager 會傳送警報。警報的電子郵件主旨列和電子郵件內容會提供有關事件狀態的資訊。SNMP 陷阱也包含有關事件狀態的資訊。
